Understanding Every Single Data & Database Dynamic

The #1 thing that confuses newcomers in this codebase is: "Where do the financial numbers ($350,000 revenue, expenses, profit) actually come from, and why aren't they stored in the SQLite database?" This guide explains every layer clearly—using real table counts inspected directly from your apps/cap/sqlite.db file.

Chapter 01 · Core Mental Model

The Two Separate Worlds of Data

Never confuse Accounting Figures (transient, never stored in our DB) with Application Metadata (saved dashboards, layouts, shares, and audit logs persisted in SQLite).

World A: Financial Accounting Data (ERP Ledger)

Journal entries, GL accounts, debit/credit amounts, company codes.

  • Local Dev Source: Hardcoded TypeScript fixture array SYNTHETIC_FINANCE_RECORDS (10 sample rows).
  • Production Source: Live SAP S/4HANA via OData (I_JournalEntryItemBasic) — currently a blocked stub.
  • Stored in SQLite/HANA? NO — NEVER
  • Lifetime: Lives in Node.js RAM for a few milliseconds during math calculation, then discarded.

World B: Application Database (Dashboard Configs & Governance)

Saved dashboard titles, widget layouts, sharing permissions, tenants, audit trails.

  • Local Dev Storage: Real SQLite database at apps/cap/sqlite.db (currently 192.5 KB).
  • Production Storage: SAP HANA Cloud (configured in apps/cap/.cdsrc.json).
  • Offline Browser Fallback: Browser localStorage["sria_saved_dashboards"] if CAP server is off.
  • Contains Raw SAP Rows? NO — only stores DashboardSpec JSON & metadata.

Chapter 04 · Local Windows Machine Map

Exact File & Storage Locations on Your Computer

If you want to inspect, back up, or reset where data lives on your Windows PC, here is every exact location.

1. Primary SQLite Database

All CAP persistence (SaveDashboard, ListDashboards, ShareDashboard, AuditEvents) writes here. Configured by .cdsrc.json & apps/cap/.cdsrc.json.

c:\Users\darla\OneDrive\Desktop\SAP,AI project\apps\cap\sqlite.db

2. Browser Fallback Cache

If the CAP backend on port 4004 is not running, the React app stores saved dashboards in your browser's local storage so demo workflows still work.

Browser DevTools → Application → Local Storage → key: sria_saved_dashboards

3. Synthetic Finance Source

The 10 sample SAP accounting postings live inside the shared TypeScript contracts package and are compiled into both CAP and Web.

packages/contracts/src/fixtures/synthetic-fixtures.ts

4. Active Session Memory (RAM)

Currently displayed dashboard, period P01/P02 series, business unit breakdown, and "Recent" sidebar items live in React memory (cleared on hard refresh unless saved).

apps/web/src/hooks/useFinanceWorkspace.ts

5. Environment & Provider Flags

Controls whether CAP uses mock or s4hana data provider and mock or live AI provider. Template is in .env.example.

.env (local, gitignored) · .cdsrc.json · apps/cap/.cdsrc.json

6. Root SQLite Stub

A small 4 KB SQLite file exists at repo root, while root .cdsrc.json explicitly redirects CAP DB reads/writes to apps/cap/sqlite.db.

c:\Users\darla\OneDrive\Desktop\SAP,AI project\sqlite.db (4 KB)
