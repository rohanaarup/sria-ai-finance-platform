## 1. Executive Summary

Phase 10 implements the complete dashboard lifecycle and intelligent conversational follow-up routing. Dashboards generated by users can now be saved into the application database, listed, reopened with transparent stale data indicators, renamed with owner authorization checks, deleted via soft-deletion/archiving, shared with read-only permissions, and refreshed on demand from the data provider.

Crucially, Phase 10 enforces **ADR-008: Zero Redundant Data Retrieval for Presentation Changes**. Follow-up prompts are classified into 4 distinct categories:
1. `PRESENTATION_ONLY`: Visual changes (switching to line chart, bar chart, or table), theme, or title changes reuse in-memory validated results with zero redundant queries to SAP/data provider.
2. `DATA_CHANGING`: Requests adding metrics (e.g., profit margin) or modifying company codes/fiscal periods trigger a fresh, authorized retrieval via the orchestrator.
3. `REFRESH`: On-demand re-execution using existing parameters pulls current postings and updates retrieval timestamps.
4. `UNSUPPORTED`: Predictive forecasting (e.g., stock price, next quarter estimates), unapproved metrics (e.g., EBITDA), or SQL/prompt injections are safely intercepted and rejected without altering dashboard state.

## 4. Key Security & Compliance Safeguards Enforced

1. **Zero Raw Financial Data Retention (Hard Privacy Rule):** Only dashboard specifications (`DashboardSpec` JSON) and query filters (`companyCode`, `fiscalYear`) are persisted in `apps/cap/sqlite.db`. Raw line items and OData response rows remain strictly transient in-memory and are never stored in the database.
2. **Reopen Stale Marker (Finance Integrity):** Reopened dashboards explicitly display `isStale: true` and a warning badge until a verified fresh query has occurred, preventing users from relying on outdated financial figures.
3. **Owner Authorization for Modifications:** Dashboard renames and deletions enforce `ownerId === ctx.userId` checks on the backend; attempts by unauthorized users return 403 Forbidden.
4. **Read-Only Sharing Boundary:** Dashboard shares default to read-only permissions (`READ`). Shared users cannot modify dashboard ownership or delete configurations.
5. **No Redis / Cache Pollution:** No caching layer was added in this phase, complying with zero-cache architecture guidelines. Presentation updates reuse already-computed in-memory figures without extra database queries.
