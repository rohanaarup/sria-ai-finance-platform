Section 03 · Data & Access Explained

Where the Data Lives, How We Access It & Where It Is Stored Locally

Answers every key question about ERP source data vs. application storage on your local Windows machine.

1. Where is the financial data right now?

Right now in local/pilot mode (FINANCE_DATA_PROVIDER=mock), all accounting figures come from 10 deterministic synthetic journal entries across Company 1000 and 2000 (FY 2026, Periods 01 & 02). In production, the target source is SAP S/4HANA entity I_JournalEntryItemBasic via SAP BTP Destination Service (currently an explicitly blocked stub).

packages/contracts/src/fixtures/synthetic-fixtures.ts
apps/cap/srv/lib/providers/s4hana-odata-provider.ts (BLOCKED stub)

2. How do we access it in code?

The React UI calls ApiClient (apps/web/src/services/api-client.ts) → Vite proxies /api/* to port 4004 → CAP OrchestrationService or FinanceDataService calls ProviderFactory.getFinanceDataProvider() → MockFinanceDataProvider.fetchRecords() → CalculationEngine aggregates in RAM and returns only MetricResult[]. If port 4004 is offline, ApiClient runs the same math locally via @sria/contracts.

apps/web/src/services/api-client.ts → apps/cap/srv/lib/providers/provider-factory.ts → apps/cap/srv/lib/finance/calculation-engine.ts

3. Where is data stored on your local device?

SQLite on disk: CAP persists saved dashboards, DashboardSpec JSON configs, shares, metric catalog rows, and metadata-only audit logs in local SQLite files.
Browser storage: If CAP is offline when saving, ApiClient caches saved dashboards in Chrome/Edge localStorage under key sria_saved_dashboards.
Raw SAP ledger rows: NEVER saved to disk or SQLite — transient in RAM only!
